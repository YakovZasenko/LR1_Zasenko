## 2. Змінений маршрут

Маршрут отримання підсумку за критичністю:
* **Браузер:** Натискання кнопки `btn-summary` у `Client/index.html` викликає подію.
* **JavaScript:** Обробник у `Client/app.js` виконує асинхронний запит `GET /api/incidents/severity-summary`.
* **API:** Маршрутизатор знаходить відповідний обробник в `IncidentEndpoints.cs`, який викликає `IncidentQueries.GetSeveritySummaryAsync`.
* **База даних:** Через `SecureLabDbContext` формується запит з агрегацією `GroupBy` до таблиці `incidents` у PostgreSQL.
* **Відповідь:** Результат перетворюється на колекцію контрактів `IncidentSeveritySummaryResponse` і повертається у форматі JSON.
* **DOM:** У `Client/app.js` безпечно створюються нові вузли, а текст вставляється через властивість `textContent`.

## 3. Виконані зміни

* Створено `IncidentSeveritySummaryResponse` (DTO) з полями `Severity` та `Count`, щоб не розкривати зайві поля сутності `Incident`.
* У `IncidentQueries.cs` реалізовано запит із застосуванням `AsNoTracking()`, групуванням та сортуванням результатів за кількістю у спадаючому порядку. Додано структуроване журналювання.
* В `IncidentEndpoints.cs` заглушку 501 замінено на ендпоінт, що повертає `200 OK`.
* У `Client/index.html` та `Client/app.js` додано кнопку, елементи статусу та відображення даних з обробкою станів завантаження, порожнього масиву та помилок.
* Оновлено сценарій у `tests/http/incidents.http`.

## 5. Security-сценарій

Для лабораторної роботи № 1 індивідуальні варіанти із навмисно вразливим станом не передбачені. Основну увагу приділено дотриманню безпечного Git-циклу без витоку секретних даних, а також роботі з межами довіри (використання безпечних властивостей DOM та DTO).

## 6. Висновок

Під час виконання лабораторної роботи було розгорнуто локальний стенд та успішно відстежено наскрізний маршрут HTTP-запиту від браузера до PostgreSQL. Реалізовано розширення API для агрегації даних, яке підтвердило важливість використання DTO для приховування внутрішніх полів сутностей бази даних. Практично доведено ефективність безпечного виводу даних через DOM-властивість `textContent`, що запобігає XSS-атакам під час відображення потенційно небезпечного тексту.
